# Vision

## Purpose
Base library for the user's home LLM chat projects; most use it to switch between models and providers within a registered list. `[confirmed: user]` interview 2026-11-07 (Vision discussion)

## Problem
The user's in-house Python apps talk to several kinds of LLM server whose APIs differ: the user's local llama-swap orchestrator for llama.cpp models (the primary way of work), OpenAI or OpenAI-compatible services, and Ollama (deprecated). `[confirmed: user]` interview 2026-11-07 (Phase 2 spec-seed round)

## Who has it
Developers of the user's own in-house Python applications. Published on GitHub, not aimed at third parties. `[confirmed: user]` interview 2026-11-07 (Phase 2 spec-seed round)

## What it offers
One asynchronous way to chat, generate, get JSON answers, run tool-calling conversations, stream replies (including model reasoning), embed text and list models, against whichever backend the app is configured for. Per-backend settings where a backend has its own (llama-swap). `[confirmed: user]` interview 2026-11-07 (Phase 3 Step 3 confirmation round)

## Success signals
1. An app switches between backends and models by choosing a different registered entry, with no code change.
2. llama-swap is first-class: what the user's llama-swap setup offers is reachable without dropping to raw HTTP.
3. Tool calling works with plain app functions, streaming or not, without the app writing its own loop.
4. The model's reasoning is visible but kept separate from the answer and from the conversation history.
5. Investigating an LLM interaction means opening one readable trace record.
6. Light to install: adds almost nothing to an app's dependencies.

`[confirmed: user]` interview 2026-11-07 (Vision discussion)

## Scope
In scope: llama-swap, OpenAI and OpenAI-compatible services; Ollama while deprecated.

## Non-goals
1. Not a public SDK: no third-party users or compatibility promises.
2. Not an agent framework: bounded tool loop only; no planning, memory or retrieval; embeddings stop at returning vectors.
3. No resilience layer: retries and failover are owned by the consuming app.
4. Not full coverage of every backend's API.
5. Text only: no image or audio.
6. Ollama is deprecated.
