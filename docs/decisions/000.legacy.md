### DEC-000-1 — The factory does not forward the app's OpenAI credential (defect)
- **Status:** open
- **Stage:** legacy · **Feature:** 000.legacy · **Step:** —
- **Date:** 2026-11-07 · **Decided by:** observed (confirmed: user)
- **Question:** When an app builds an OpenAI client through the factory, which credential is used?
- **Decision:** Observed, and a defect: `get_llm_client("openai", …)` does not forward `bearer_token`; the client falls back to the environment (DEC-000-2). A token passed for `openai` is discarded without warning; `llamaswap` and `ollama` forward it. Consequence: a factory-built `openai` client pointed at any address sends the environment's key to that address.
- **Reason:** No valid reason; the user called it a mistake: "It was a mistake. Token is provided by APP and never from ENV. App reads it from ENV." `[confirmed: user]` The factory comment ("the token is now read from the environment variable within the client") records the intent at the time, unchanged since the initial commit. `[confirmed: llm/llm.py:27]` The fix is a roadmap item.
- **Lands in:** `llm/llm.py:26-28`
- **Cites:** docs/architecture/interfaces.md § Exposed: factory; US-003.AC-1 (not met)

### DEC-000-5 — One shared settings merge; unknown names dropped; "nothing" removes the setting
- **Status:** accepted
- **Stage:** legacy · **Feature:** 000.legacy · **Step:** —
- **Date:** 2026-11-07 · **Decided by:** observed (confirmed: user)
- **Question:** How are a backend's built-in settings, the client's default settings and the per-call settings combined?
- **Decision:** `_merge_options_base` copies the backend's built-in table, then applies the client's `default_options`, then the call's `options`. Each key is resolved through the backend's alias map and kept only if it is in the supported table (otherwise silently skipped). `None` values are stripped after merging, so `None` at a higher layer removes the key, including its built-in value. When an alias and its main name appear in one layer, the later one in dict order wins; across layers the call layer wins. Each backend's `_merge_options` post-processes the result (OpenAI maps `enable_thinking` to `reasoning_effort`; llama-swap drops `reasoning_effort`). Ollama's mirostat handling is not part of this entry.
- **Reason:** One settings dict can be passed to any backend `[confirmed: user]`. `None` means defer to the server `[confirmed: user]`. The alias semantics are kept as they are `[confirmed: user]`.
- **Rejected:** Strict validation that raises on unknown names — the user declined; the Ollama module docstring claiming it is stale. "None = inherit the lower layer" — the user declined.
- **Lands in:** `llm/llm_client.py:124-149`, `llm/openai.py:45-61`, `llm/llama_swap.py:47-60`
- **Cites:** docs/architecture/data-model.md § Settings; docs/architecture/subsystems.md § Options layer; US-015.AC-1, US-016.AC-1, US-017.AC-1..2

### DEC-000-46 — Records are written in clear text, flushed per line, synchronously
- **Status:** accepted
- **Stage:** legacy · **Feature:** 000.legacy · **Step:** —
- **Date:** 2026-11-07 · **Decided by:** observed (confirmed: user)
- **Question:** How are trace records written, and what do they contain?
- **Decision:** Every write is flushed (`llm/trace.py:33-35`); the file is UTF-8. Payloads are JSON with `indent=2, ensure_ascii=False, default=str`, falling back to `str()` (`llm/trace.py:149-153`). Writes are synchronous inside async calls. Nothing is redacted. Headers never reach the tracer, so the bearer token is never written (`llm/openai.py:104,113-115`; `llm/llama_swap.py:99,108-110`). Error text, including the URL and the server reply, is written as is.
- **Reason:** Tracing is a debugging aid only, so clear text, blocking writes and best-effort records are accepted `[confirmed: user]`. Credentials embedded in the server address are not covered by the never-written rule `[confirmed: user]`. Flushing per line keeps the record readable mid-call `[inferred]`.
- **Lands in:** `llm/trace.py:23-93,149-153`
- **Cites:** docs/architecture/data-model.md § Trace record; US-049.AC-7; DEC-000-12

### DEC-000-47 — Trace scope: errors recorded and re-raised; trace I/O can change the call's outcome
- **Status:** open
- **Stage:** legacy · **Feature:** 000.legacy · **Step:** —
- **Date:** 2026-11-07 · **Decided by:** observed (confirmed: user)
- **Question:** What does the trace scope do with the call's errors, and what happens when the trace itself cannot be written?
- **Decision:** `except Exception` logs `<Type>: <message>` and re-raises; `finally` writes the footer and closes the file (`llm/trace.py:122-129`). A `CancelledError` is recorded with no ERROR section. The folder and file are created outside any guard (`llm/trace.py:116,120`), so an unwritable folder fails the call before it is sent. A write failure inside the `except` or `finally` replaces the original error and skips `f.close()`, leaking the file (`llm/trace.py:124-129`).
- **Reason:** Re-raising lets the app see the same error `[inferred]`. Open: the call must go ahead untraced when the record cannot be written — a defect; a trace write failure must not hide the call's error or leak the file — a defect `[confirmed: user]`.
- **Lands in:** `llm/trace.py:110-129`
- **Cites:** docs/architecture/subsystems.md § Tracer (`LLMTracer`); US-050.AC-1, US-050.AC-4; US-050.AC-2, US-050.AC-3 (not met)

### DEC-000-52 — Repeated filling is an iterative loop with a fixed pass cap
- **Status:** open
- **Stage:** legacy · **Feature:** 000.legacy · **Step:** —
- **Date:** 2026-11-07 · **Decided by:** observed (confirmed: user)
- **Question:** How does repeated placeholder filling terminate?
- **Decision:** `for _ in range(10)`, then `re.findall(r"{{(\w+)}}")`; it stops only when no slot is found (`llm/llm.py:69-76`). Callable values are called per occurrence and per pass, then `str()` is applied (`llm/llm.py:75-76`). It stops silently at the cap. An unknown slot keeps the found list non-empty, so all passes run.
- **Reason:** "Safer, iterative replacement to avoid runaway recursion" `[confirmed: llm/llm.py:67]`; "up to 10 passes to avoid runaway loops" `[confirmed: llm/llm.py:62]`; "Lazily evaluates callables" `[confirmed: llm/llm.py:63]`. The silent cap and raw callable errors are accepted `[confirmed: user]`. Open: stop as soon as nothing more can be filled — a defect `[confirmed: user]`.
- **Lands in:** `llm/llm.py:59-77`
- **Cites:** docs/architecture/interfaces.md § Exposed: utilities; US-054.AC-1, US-054.AC-2; US-054.AC-3 (not met); US-054.AC-5; US-055.AC-1, US-055.AC-2, US-055.AC-3
