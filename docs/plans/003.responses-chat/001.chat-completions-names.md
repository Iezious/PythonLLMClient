## Interface intent

- **`OpenAIChatCompletionsClient`** (new, `llm/openai_chat_completions.py`): the current OpenAI client, renamed; same constructor, methods, settings tables and behaviour (chat completions, credential required). Extends `LLMClient` directly (DEC-003-7, DEC-arch-1, DEC-arch-2).
- **`LlamaSwapChatCompletionsClient`** (new, `llm/llama_swap_chat_completions.py`): the current llama-swap client, renamed; same constructor, methods, tables and behaviour (DEC-003-7).
- **`LLMSettingIgnoredWarning`** (new, `llm/exceptions.py`): the library's ignored-setting warning category, a `UserWarning` subclass with no behaviour of its own (DEC-003-5).
- **`get_llm_client`** (changed, `llm/llm.py`): gains a trailing optional `protocol` argument; selects the class per DEC-003-8 / DEC-arch-4 and forwards the other arguments unchanged. `llm/llm.py`'s `__all__` lists the two new class names.
- **Package exports** (`llm/__init__.py`): add the two chat-completions classes and `LLMSettingIgnoredWarning` to the imports and `__all__`; `__version__` per DEC-003-14. `OpenAIAPIClient` / `LlamaSwapAPIClient` keep their exports (they change meaning in steps 002 / 004).
- **Project metadata** (`pyproject.toml`, `uv.lock`): version per DEC-003-14.
- **README** (`README.md`): documents the two protocols and their four class names, the factory's `protocol` argument and its refusals, the warning category, and that tool conversations on the Responses classes are not available yet (use the chat-completions class meanwhile, DEC-003-4).
- `llm/openai.py` and `llm/llama_swap.py` are **not** edited in this step.

## Definition of done

1. [test] `OpenAIChatCompletionsClient`, `LlamaSwapChatCompletionsClient` and `LLMSettingIgnoredWarning` are importable from `llm` and listed in `llm.__all__`; the two classes are distinct from `OpenAIAPIClient` / `LlamaSwapAPIClient` and neither subclasses the other (DEC-003-7, DEC-arch-2, DEC-003-5).
2. [test] `LLMSettingIgnoredWarning` is a subclass of `UserWarning` and can be filtered by its category (DEC-003-5, DEC-arch-6).
3. [test] `get_llm_client` for `openai` and `llamaswap` with no protocol, and with `protocol="responses"`, returns `OpenAIAPIClient` / `LlamaSwapAPIClient` (US-056.AC-1, DEC-003-8).
4. [test] `get_llm_client` with `protocol="chat_completions"` returns `OpenAIChatCompletionsClient` / `LlamaSwapChatCompletionsClient` carrying the given model, address, time limit, credential and default settings (US-056.AC-2, DEC-003-8).
5. [test] The class chosen never depends on the address: the same protocol choice with an OpenAI-looking and a local address gives the same class (US-056.AC-3).
6. [test] An unknown protocol value (including a different case such as `"Responses"`) raises `ValueError` naming the value (DEC-arch-4, DEC-003-8).
7. [test] `server_type="ollama"` with any protocol given raises `ValueError` whose message says the protocol choice is not offered on Ollama; without a protocol it still returns the Ollama client (US-056.AC-5, DEC-003-8).
8. [test] The factory still refuses an unknown server type with `ValueError` naming it, still refuses an OpenAI client without a credential (either protocol), and still builds llama-swap with or without one (US-002.AC-1, US-003.AC-2, US-005.AC-1).
9. [test] A `chat` on each chat-completions class sends its request to `/chat/completions` (US-056.AC-2).
10. [test] `llm.__version__` equals the `pyproject.toml` version and both are `0.3.0` (DEC-003-14).
11. [test] Every listed unit test file constructs the chat-completions classes wherever it exercised today's OpenAI or llama-swap behaviour, and the whole moved suite passes with no change to its assertions (DEC-arch-12).
12. [test] (live) Every listed integration file uses the chat-completions classes (direct construction, or the factory with `protocol="chat_completions"`) and passes against llama-swap and, when a key is present, OpenAI (DEC-arch-12, US-056.AC-2).
13. [manual/live] `README.md` describes both protocols, the four class names, the factory `protocol` argument, the warning category, and the interim tool-conversation refusal on the Responses classes.
14. [manual/live] `uv run ruff check llm/` is clean; a diff of each new module against its source module shows only the class-name, docstring and module-header changes (DEC-003-7).
