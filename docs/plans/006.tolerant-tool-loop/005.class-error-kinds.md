# Step 005 — Error kinds at the classes' own raise sites

## Goal

Give every `LLMError` raised by the four OpenAI-family classes themselves (outside tool execution) its `kind` per DEC-arch-19, each class edited in its own module, messages unchanged (~60 LoC of one-line edits).

## Source files

- llm/openai.py
- llm/llama_swap.py
- llm/openai_chat_completions.py
- llm/llama_swap_chat_completions.py

## Test files

- tests/test_responses_error_kinds.py
- tests/test_chat_completions_error_kinds.py

## Interface intent

No new or renamed functions. Raise sites in each class gain a `kind`:

- **`invalid_reply`** — unreadable 2xx body on model listing / embeddings, malformed model-list or embeddings reply (entry without id / vector, count mismatch), a Responses reply that is not a mapping, `chat_json` parse failure.
- **`server_failed`** — a Responses reply reporting failure (non-streamed), a Responses stream failure / error event, chat or tool round.
- **`incomplete`** — a Responses incomplete reply (non-streamed or streamed), a Responses stream that ends without its completion event, and a tool round cut at the app's output limit that requests a tool (DEC-arch-13), chat or tool round.
- The tool-execution helpers' raise sites (`not_offered`, `bad_arguments`, `unserialisable_result` → `tool`) are **not** part of this step; they move with each class's tool-loop step. Raw `KeyError` / `IndexError` on malformed chat-completions replies and existing `RuntimeError` / `ValueError` raises are unchanged.

## Definition of done

- DoD-1 [test] On `OpenAIAPIClient` and `LlamaSwapAPIClient`: a non-streamed reply that is not a mapping raises `LLMError` with `kind == "invalid_reply"`; a failed reply raises with `kind == "server_failed"`; an incomplete reply not cut at the app's own limit raises with `kind == "incomplete"`; texts unchanged. Cites US-067.AC-2, US-067.AC-3.
- DoD-2 [test] On both Responses classes, streamed `chat`: a failure / error event raises `LLMError` with `kind == "server_failed"`; a stream that ends without its completion event, or that reports incompleteness not at the app's own limit, raises with `kind == "incomplete"`. Cites US-067.AC-2.
- DoD-3 [test] On both Responses classes, `chat_with_tools` streamed and not: a failed tool round raises with `kind == "server_failed"`; an incomplete tool round, and a round cut at the app's own output limit that requests a tool, raise with `kind == "incomplete"` and no tool runs. Cites US-067.AC-2.
- DoD-4 [test] On all four OpenAI-family classes: malformed or unreadable model-list and embeddings replies raise `LLMError` with `kind == "invalid_reply"`. Cites US-067.AC-2.
- DoD-5 [test] On all four OpenAI-family classes: `chat_json` with an expected shape whose reply does not parse as JSON raises `LLMError` with `kind == "invalid_reply"`. Cites US-067.AC-2.
- DoD-6 [manual/live] The step-002 typing test and the rest of the existing unit suite stay green (texts and exception types unchanged).
