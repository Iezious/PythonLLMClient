## Interface intent

- **Version** — `pyproject.toml` `version` and `llm/__init__.py` `__version__` both `0.2.1` (DEC-arch-23); `uv lock` refreshed.
- **README.md** — updated for the release (prose and short examples, no internals):
  - Tool Calling: tolerant handling is the default (the model is told, the conversation continues; failure kinds listed; model-facing texts carry no exception text), `tool_errors="raise"` restores the old behaviour, cancellation and the round limit unchanged; a note that this default changed in 0.2.1.
  - Tool event observer: `on_tool_event`, the `ToolEvent` fields, event order, plain or async observer, strict vs tolerant observer-failure rules, `LLMToolObserverWarning`.
  - Tools accepting `**kwargs` run with whatever arguments the model sends.
  - Errors: `LLMError` with `kind` (the `LLMErrorKind` names and what each means) and `status` for refused requests; text form unchanged.
  - Time limits: `timeout` (total per request) and `read_timeout` (silence limit on streamed replies, OpenAI family; refused with Ollama at the factory).
  - Debug Trace Logging: the `trace` constructor / factory argument (`None` → environment, `False` → never, `True` → folder from `LLM_TRACE_FOLDER`, refused without it); tolerant failures in the record.
  - Ollama (deprecated) does not accept `tool_errors`, `on_tool_event`, `read_timeout`.
- **Root `AGENTS.md`** — Common Commands gains `uv run mypy --strict llm` (DEC-arch-22, DEC-006-1); the Key Patterns base-class line states the base holds transport plumbing only and each class keeps its own copy of its behaviour, the tool loop included (subsystems.md § Base client); any line describing `chat_with_tools` messages as a list of string dicts is updated to the read-only sequence of mappings; the Conventions line about typed options mentions the generic base and the mypy gate.
- **Live test** (`tests/integrations/test_responses_tool_failures.py`) — per DEC-006-12.
