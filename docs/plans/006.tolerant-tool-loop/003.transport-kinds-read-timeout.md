# Step 003 — Transport: error kinds and status in the base, silence limit (read_timeout)

## Goal

Give every `LLMError` raised by the base's transport plumbing and shared stream parsers its `kind` (and `status` for non-2xx), and add the optional silence limit `read_timeout` on streamed requests through the base, the four OpenAI-family constructors and the factory (~90 LoC).

## Interface intent

- **Base request plumbing** (`_request`, `_stream_post`, and read failures surfacing while a stream is consumed through the SSE reader) — non-2xx raises `LLMError` with `kind="status"` and `status` = the HTTP status; transport failures raise with `kind` `timeout` / `interrupted` / `connection` matching today's text kinds; messages unchanged (DEC-arch-19, DEC-001-7).
- **Base shared chat-completions stream parsers** — in-stream error frame → `kind="server_failed"`; stream that ends without a completion signal → `kind="incomplete"`. The parsers gain no other behaviour (subsystems.md § Base client).
- **Base `embed`** — empty embedding result → `kind="invalid_reply"`.
- **`LLMClient` constructor** (changed) — keyword-only optional `read_timeout` (seconds, or none), stored as client state (DEC-006-5).
- **`_stream_post`** (changed) — opens the streamed request with the unchanged total limit plus, when `read_timeout` is set, the HTTP library's per-read limit; with none set, no per-read limit. Non-streamed `_request` keeps the total limit only (DEC-arch-20).
- **Four OpenAI-family constructors** (changed) — accept keyword-only `read_timeout` and forward it to the base.
- **`get_llm_client`** (changed) — keyword-only `read_timeout` after `protocol`, forwarded by keyword to the chosen OpenAI-family class; with `server_type="ollama"` and `read_timeout` given (not none) it raises `ValueError` naming the argument and the reason (DEC-arch-24, DEC-006-5).

## Definition of done

- DoD-1 [test] A non-2xx reply on a non-streamed request raises `LLMError` with `kind == "status"` and `status` equal to the HTTP status; its text is as before. Cites US-067.AC-1, US-067.AC-3.
- DoD-2 [test] A non-2xx reply on a streamed request raises `LLMError` with `kind == "status"` and the HTTP status; the text still carries the address and the server's reply and never the credential. Cites US-067.AC-1, US-067.AC-3.
- DoD-3 [test] Transport failures on plain and streamed requests (connection refused / unreachable, timeout, transfer interrupted mid-stream) raise `LLMError` with `kind` `connection`, `timeout`, `interrupted` respectively, texts unchanged (`Request to <url> failed: <kind>`). Cites US-067.AC-2, US-067.AC-3.
- DoD-4 [test] In the shared chat-completions stream parsers, an error frame raises `LLMError` with `kind == "server_failed"` and a stream ending without finish reason or done frame raises with `kind == "incomplete"`. Cites US-067.AC-2.
- DoD-5 [test] Base `embed` with an empty result raises `LLMError` with `kind == "invalid_reply"`. Cites US-067.AC-2.
- DoD-6 [test] With `read_timeout` set on an OpenAI-family client, a streamed request is opened with that per-read limit and the unchanged total limit; a non-streamed request on the same client is opened with the total limit only; without `read_timeout` streamed requests carry no per-read limit. Cites US-068.AC-3; DEC-arch-20.
- DoD-7 [test] Against a local streaming server (DEC-006-11), a streamed chat whose server goes silent longer than `read_timeout` ends with `LLMError` of `kind == "timeout"`. Cites US-068.AC-1.
- DoD-8 [test] Against the same local server, a streamed chat whose pieces keep arriving at gaps shorter than `read_timeout` but whose total duration exceeds it completes and returns the full text. Cites US-068.AC-2.
- DoD-9 [test] `get_llm_client` forwards `read_timeout` to the class it picks for `openai` and `llamaswap` on both protocols; with `ollama` and a `read_timeout` it raises `ValueError` naming `read_timeout`; without `read_timeout` every backend builds as before. Cites US-068.AC-1; DEC-arch-24.
- DoD-10 [test] `OllamaAPIClient(...)` given `read_timeout` raises `TypeError` (the argument is not declared). Cites DEC-arch-24.
- DoD-11 [manual/live] The step-002 typing test (`tests/test_typing_contract.py`) and the rest of the existing unit suite stay green.
