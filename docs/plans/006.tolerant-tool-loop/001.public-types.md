# Step 001 — Public types, error attributes and the observer warning

## Goal

Add the release's public data definitions — `ToolEvent`, `ToolErrorKind`, `LLMErrorKind`, `LLMToolObserverWarning` — and give `LLMError` keyword-only `status` and `kind` attributes with its text form unchanged, all exported from the package top level (~60 LoC).

## Source files

- llm/tool_events.py
- llm/exceptions.py
- llm/__init__.py

## Test files

- tests/test_llm_error.py
- tests/test_package_surface.py

## Interface intent

- **`ToolErrorKind`** (new, `llm/tool_events.py`) — closed literal set of the five tool failure kind names (data-model.md § Tool events).
- **`ToolEvent`** (new, `llm/tool_events.py`) — total typed dictionary with the six fields of data-model.md § Tool events: `type` (literal `start` / `result` / `error`), `name` (text), `call_id` (text or none), `arguments` (text), `output` (text or none), `error_kind` (`ToolErrorKind` or none). DEC-006-4.
- **`LLMErrorKind`** (new, `llm/exceptions.py`) — closed literal set of the eight error kind names (data-model.md § Error kinds).
- **`LLMError`** (changed) — constructor keeps `message` and optional `description` and gains keyword-only optional `status` (integer HTTP status or none) and `kind` (`LLMErrorKind` or none), both stored as public attributes defaulting to none. Text form unchanged. Fully annotated (including its text-form method).
- **`LLMToolObserverWarning`** (new, `llm/exceptions.py`) — library warning category, a subclass of `UserWarning`, documented as emitted when the tool-event observer fails in tolerant mode.
- **Package exports** (`llm/__init__.py`) — the four new names re-exported and listed in `__all__` (DEC-006-3).

## Definition of done

- DoD-1 [test] `LLMError` built with only a message (and optionally a description) has `status` and `kind` equal to none, and its text form is exactly as before (`message` / `message: description`). Cites US-067.AC-3.
- DoD-2 [test] `LLMError` accepts `status` and `kind` only as keyword arguments and exposes them unchanged as attributes; passing them does not change the text form. Cites US-067.AC-1, US-067.AC-3.
- DoD-3 [test] `LLMErrorKind` lists exactly `status`, `timeout`, `connection`, `interrupted`, `invalid_reply`, `server_failed`, `incomplete`, `tool`. Cites US-067.AC-2.
- DoD-4 [test] `ToolErrorKind` lists exactly `not_offered`, `bad_arguments`, `unknown_argument`, `tool_raised`, `unserialisable_result`; `ToolEvent` declares exactly the six keys `type`, `name`, `call_id`, `arguments`, `output`, `error_kind`, all required. Cites US-065.AC-1, US-065.AC-3.
- DoD-5 [test] `LLMToolObserverWarning` is a `UserWarning` subclass distinct from `LLMSettingIgnoredWarning`, so an app can filter it on its own. Cites US-065.AC-9.
- DoD-6 [test] `LLMErrorKind`, `LLMToolObserverWarning`, `ToolEvent` and `ToolErrorKind` are importable from `llm` and present in `llm.__all__`, alongside every previously exported name.
