# Step 004 — Per-client trace switch and the tool-error trace entry

## Goal

Add the three-state `trace` argument to all five client constructors and the factory, resolved once at creation through a private path in the tracer, and add the trace session's tool-error entry that the tool-loop steps use (~90 LoC).

## Interface intent

- **Tracer private construction path** (new, `llm/trace.py`; exact name chosen by the skeleton) — takes the switch value (`None` / `False` / `True`) and returns an `LLMTracer`: `None` → today's environment read; `False` → disabled regardless of the environment; `True` → enabled with the folder from `LLM_TRACE_FOLDER` without consulting `LLM_TRACE`, raising `ValueError` naming `LLM_TRACE_FOLDER` when it is unset or empty. The public `LLMTracer()` constructor is unchanged (DEC-006-6, DEC-arch-27).
- **Trace session `log_tool_error(name, note)`** (new) — writes a `TOOL ERROR: <name>` section with the note text; a no-op on the disabled session; write failures follow DEC-002-12 (DEC-006-7).
- **`LLMClient` constructor** (changed) — keyword-only optional `trace`; builds its tracer once through the private path, so the `True`-without-folder refusal surfaces at client creation (DEC-006-5).
- **Five client constructors** (changed) — accept keyword-only `trace` and forward it to the base; `OllamaAPIClient` only passes it through (DEC-arch-24, DEC-006-13).
- **`get_llm_client`** (changed) — keyword-only `trace` after `read_timeout`, forwarded by keyword to every backend's class.

## Definition of done

- DoD-1 [test] A client built with `trace=False` writes no trace record for a call even when `LLM_TRACE` is true-like and `LLM_TRACE_FOLDER` names a folder. Cites US-069.AC-1.
- DoD-2 [test] A client built with `trace=True` and `LLM_TRACE_FOLDER` set writes a record for a call while `LLM_TRACE` is unset or false-like. Cites US-069.AC-2.
- DoD-3 [test] Building a client with `trace=True` while `LLM_TRACE_FOLDER` is unset or empty raises `ValueError` whose message names the missing trace folder setting; no server is contacted. Cites US-069.AC-3.
- DoD-4 [test] A client built without `trace` traces exactly when the environment enables it (true-like `LLM_TRACE` and non-empty `LLM_TRACE_FOLDER`), as before. Cites US-069.AC-4.
- DoD-5 [test] DoD-1–DoD-3 hold for each of the five client classes built directly (Ollama included), and `get_llm_client` forwards `trace` to the class it picks for every `server_type` / `protocol` combination. Cites US-069.AC-1, US-069.AC-2, US-069.AC-3.
- DoD-6 [test] `LLMTracer()` built with no arguments behaves as before (environment decides). Cites US-069.AC-4.
- DoD-7 [test] On an enabled trace session, `log_tool_error(name, note)` writes a `TOOL ERROR: <name>` section carrying the note inside the record; on a disabled session it writes nothing; a write failure during it never raises out of the session (DEC-002-12). Cites US-065.AC-13.
- DoD-8 [manual/live] The step-002 typing test and the rest of the existing unit suite stay green.
