# Step 007 — llama-swap Responses chat: a reply cut at the app's own output limit is returned

## Goal

On `LlamaSwapAPIClient`, a non-streamed or streamed chat-style reply (chat, generate, JSON-only) that the server reports as stopped at the output limit the app set is returned as text instead of raising. Every other early end stays an error (DEC-arch-13, chat part; own copy per DEC-arch-2; tool rounds are feature 004's).

## Source files

llm/llama_swap.py

## Test files

tests/test_llamaswap_responses_output_limit.py

## Interface intent

- **Non-streamed reply reader** (module-level helper, changed): gains the keyword-only output-limit flag of DEC-003-17 / DEC-003-20 (default off). Input: the reply mapping and the flag. Output: the extracted text. With the flag on and a cut at the app's limit (DEC-003-18), it extracts the text as for a completed reply (DEC-003-19); otherwise unchanged (DEC-003-12).
- **Responses stream parser** (private method, changed): gains the same keyword-only flag (default off). Inputs: the open streamed response, the optional receiver, the flag. Output: the full text delivered. With the flag on and a matching incomplete event, it ends as at the completed event (DEC-003-19); otherwise unchanged (DEC-003-13).
- **`chat`** (changed, streamed and non-streamed paths): computes the flag from its wire settings (DEC-003-17) and passes it to the reader / parser it calls. `generate` changes only through `chat`.
- **`chat_json`** (changed): computes the flag the same way and passes it to the non-streamed reader; its JSON parse check is unchanged.
- Docstrings of the reader, the parser, `chat`, `generate` and `chat_json` state the new rule, including the accepted llama-swap gap of DEC-arch-13 (the server reports a capped reply as completed, so a cut it does not report is returned as text whoever set the limit).
