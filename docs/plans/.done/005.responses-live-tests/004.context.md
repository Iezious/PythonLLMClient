# Step 004 — step-specific context

- **What 004 delivers that this step relies on** (`docs/plans/004.responses-tools/`):
  - the Responses tool loop, streamed and not, with the signature unchanged;
  - tool definitions flattened, with a pydantic-built definition accepted (004 step 001 DoD-1, DEC-004-5, DEC-004-1);
  - caller-supplied tool-call and tool-result turns converted by shape to `function_call` / `function_call_output` items (DEC-004-6; covered by unit test in 004 step 001 DoD-10);
  - `response_format` sent as the text format on every round (DEC-004-10).

  The T2 check here (DoD-3) is the live counterpart of that unit coverage. It is not a gap.
- **Not repeated here:** 004's live tests (DEC-004-13): the two-round reasoning-model test, protocol parity with one tool, and the json_object final answer.
- **Shape of the caller history with tool turns** (data-model § Message; DEC-005-11):
  - the assistant turn is `{"role": "assistant", "content": "", "tool_calls": [{"id": "call_prev_c", "type": "function", "function": {"name": "fetch_record", "arguments": "{\"record_id\": \"C\"}"}}]}`;
  - the result turn is `{"role": "tool", "content": <record C value>, "tool_call_id": "call_prev_c"}`.

  Copy the list before the call to compare afterwards.
- **Tool values.** Each record id maps to a fixed value that cannot be guessed (e.g. `amber-7310` for A). The tool also counts calls per id. Assertions use the recorded ids, never the answer's wording.
- **Streamed answer containment.** On the tool path the receiver gets every round's text and reasoning, but only the final answer is returned (interfaces § Streaming callback). So the check is containment, not equality.
- **Pydantic.** It is needed for the typed-definition test. The `dev` extra is installed for live runs (tests/integrations/AGENTS.md § Conventions).
