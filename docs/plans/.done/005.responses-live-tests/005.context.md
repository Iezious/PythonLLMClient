# Step 005 — step-specific context

- **What the tool checks rely on** (DEC-arch-13, tool part; DEC-004-16, DEC-004-17). With the app's limit set, a tool round cut at that limit with no tool call is the answer and is returned, streamed and not. A cut round that holds a tool call ends with `LLMError` and its tools do not run. On llama-swap the server reports a capped round as `completed`, so the round is read as a complete one (DEC-arch-13 llama-swap gap).
- **Why the model is told no tool is needed.** The wanted path is: the first round answers in prose and is cut there. If the model calls the tool anyway, a call that fits in 16 tokens runs and the next round's answer is cut, which is still US-062.AC-4. A call cut mid-arguments ends with `LLMError`, which is correct library behaviour, not a finding (DEC-005-13). The test does not assert whether the tool ran; that is the model's choice.
- **Tool.** One neutral tool with one text argument, a name and a value that cannot be guessed (tests/integrations/AGENTS.md § Conventions). Its definition is in today's nested `function` shape. It is written in this file; step 004's helpers are not imported (DEC-005-2).
- **Streamed tool answer.** The check is containment of the stripped return in the recorder text, not equality, for the reason given in `004.context.md` § Streamed answer containment.
- **chat_with_tools signature.** As in `docs/plans/004.responses-tools/context.md` § Cross-cutting constraints. `max_loops` stays at its default.
- **chat_json cut.** The expected shape only turns on the parse check (`context.md` § Library surface). With no `response_format` in the options the class asks for the plain JSON text format, not a `json_schema` grammar, so DEC-005-9 does not apply. OpenAI's JSON mode needs the word "JSON" in the conversation, so the prompt names it (DEC-005-14). Before feature 003 step 006 lands, the OpenAI variant also ends with `LLMError` (from the incomplete reply) and can pass early; it is a valid check only once the dependency is done.
- **Not checked here.** A cut inside a tool-call round, and a length stop with no app limit (US-062.AC-6), are unit-covered by feature 004 steps 005 / 006 (DoD-4, DoD-6, DoD-7) and feature 003 steps 006 / 007 (DoD-4, DoD-5) (DEC-005-13, DEC-005-15).
- **Decision pointers:** DEC-005-12 (cut checks, notice filter, models), DEC-005-13 (tool prompt and checks), DEC-005-14 (JSON cut), DEC-005-15 (AC-6 not live), DEC-005-16 (step split, ordering).
