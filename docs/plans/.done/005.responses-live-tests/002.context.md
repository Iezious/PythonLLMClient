# Step 002 — step-specific context

- **What the token cap is checked against (DEC-arch-13).** The library sends `max_tokens` as `max_output_tokens` (DEC-003-9). The app set the limit when `max_tokens` (or an alias) is in the merged settings, whether from the call options (DoD-1, DoD-2, DoD-8) or from the client defaults (DoD-9). When the reply is cut at that limit, the call returns the text produced:
  - non-streamed, from a reply with status `incomplete` and reason `max_output_tokens`, extracted as from a completed reply (DEC-003-19);
  - streamed, `response.incomplete` with that reason ends the stream as `response.completed` does, an open reasoning block is closed, and the return equals what the receiver got (DEC-003-19).

  The test asserts only the structure of DEC-005-6 / DEC-005-12. It never asserts the exact text and never asserts that the reply was in fact cut.
- **What each backend reports.** OpenAI reports the cut as `incomplete`, so its variants pass only once feature 003 step 006 is done. llama.cpp reports a capped reply as `completed`, with no incomplete details and the stream ending `response.completed` (verify run 1 of this feature; DEC-arch-13 llama-swap gap). Its variants pass through the completed path, as they did before the replan.
- **Not checked here.** The other early stops of US-024.AC-2 are unit-covered by feature 003 steps 006 / 007 (DoD-6, DoD-7). US-062.AC-6: see `context.md` § Stories verified live.
- **Thinking off and the cap.** On llama-swap the cap applies with thinking off (DEC-005-4), so the 16 tokens go to answer text, not reasoning.
- **Client default cap (DoD-9).** Build the client with `default_options` holding the cap through the helper's builder. For llama-swap the builder merges it over thinking off (step 001 Interface intent); the call options then carry no cap.
- **Ignored setting and warnings.** The no-counterpart keys on both classes are `presence_penalty`, `frequency_penalty`, `seed`, `stop` and `logit_bias` (DEC-003-9). This step uses `seed` (DEC-005-8). Count warnings inside `warnings.catch_warnings(record=True)` + `simplefilter("always")`, filtered to `LLMSettingIgnoredWarning`, so that unrelated warnings (aiohttp, pydantic) do not change the count. The cut checks use the wider filter of DEC-005-12 on the same kind of recording.
