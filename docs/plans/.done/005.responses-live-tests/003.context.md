# Step 003 — step-specific context

- **What the error checks are tested against** (from the spec; never quote library message text beyond these):
  - **Non-2xx reply, streamed or not.** `LLMError` carrying the request address and the server's reply as its description, never the credential (DEC-000-11, DEC-arch-5, interfaces § Exposed: error contract).
  - **Transport failure.** `LLMError` carrying the address. Any credential in the transport text is redacted (DEC-001-7).
- **Never skipped.** The bad-credential tests pass the dummy key as the builder's credential override, so the helper's key reader (and its skip) is not used. The OpenAI unreachable-server test does the same. Both test families run without any real key or remote server, except that the bad-credential test needs outbound HTTPS to OpenAI's address. If that is unreachable, the run reports it as requires-live-run.
- **Closed port.** Port 1 on 127.0.0.1 normally refuses at once. The 10 s time limit (DEC-005-8) bounds a filtered port. Either way, the expected outcome is `LLMError` naming the address.
- **Session facts.** The session is created lazily, closed at scope exit and recreated by a later call. The only shared per-client state is the ignored-setting record (DEC-000-24, DEC-003-6). The concurrent test sends no ignored setting.
- **Embedding client.** The client is built with the embedding model as its `model` (DEC-005-3). `embed` and `embed_batch` take no chat settings. The llama-swap thinking-off client default is harmless here, because embeddings send no generation settings (US-041.AC-4).
- **Existing embedding coverage.** `test_llm_integrations.py` covers `embed`, `embed_batch` and `get_models` on the chat-completions classes. This step covers the Responses classes, which keep their own copies (US-057.AC-2).
- **Decision pointers:** DEC-005-7 (similarity order), DEC-005-8 (dummy key, address, time limit), DEC-005-10 (concurrency shape).
