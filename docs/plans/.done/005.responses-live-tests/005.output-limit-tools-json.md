# Step 005 — Cut tool answer and cut checked JSON answer on Responses

## Goal

This step adds live tests on both Responses classes for the following:

- a tool conversation whose final answer is cut at the token cap the app set returns the cut answer, streamed and not (US-062.AC-4);
- a checked JSON answer cut at that cap ends with the same error as any invalid JSON answer (US-062.AC-5).

The step is test-only (DEC-005-1). It is split from step 002 so that the tool helpers live in a file of their own and step 002 stays one coherent file (DEC-005-16). A cut inside a tool-call round is not forced live; it is unit-covered by feature 004 steps 005 / 006 (DEC-005-13).

## Source files

none

## Test files

tests/integrations/test_responses_output_limit.py

## Interface intent

**Library interfaces.** None added or changed.

**Test file.** It uses `tests.integrations.live_support` (step 001) for clients, the recorder, the answer-text extraction, the marker checks and the well-formed-block check. It holds module-local helpers:

- the long-answer prompt and the system instruction that tells the model no tool is needed (DEC-005-13);
- one neutral tool callable that records its calls, and its nested definition (DEC-005-13);
- the long-JSON prompt and the expected shape passed to `chat_json` (DEC-005-14);
- the "no library notice" check of DEC-005-12.

Nothing is imported from another step's test file (DEC-005-2).

## Definition of done

1. [test] (live) Non-streamed `chat_with_tools` with the neutral tool offered, the long-answer prompt, the no-tool system instruction and the token cap of DEC-005-8 as a call option, on both backends (OpenAI with `OPENAI_MODEL`, llama-swap thinking off). The call returns text with no `LLMError`; the answer text is non-empty; the reply holds no reasoning marker; no warning of the `UserWarning` family is recorded (US-062.AC-4, US-057.AC-1, DEC-arch-13, DEC-005-12, DEC-005-13).
2. [test] (live) The same request, streamed with a recorder, on both backends. The call returns text with no `LLMError`; its answer text is non-empty; the returned answer is contained in the recorder output; the recorder output passes the well-formed-block check; no warning of the `UserWarning` family is recorded (US-062.AC-4, US-062.AC-2, US-057.AC-1, DEC-arch-13, DEC-005-12, DEC-005-13).
3. [test] (live) `chat_json` with an expected shape given, no `response_format` in the options, the long-JSON prompt and the token cap of DEC-005-8 as a call option, on both backends. The call ends with `LLMError`. Neither variant is marked as an expected failure (US-062.AC-5, DEC-000-37, DEC-arch-13, DEC-005-14).
