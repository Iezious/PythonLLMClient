# Step 004 — Extra live tool conversations on Responses

## Goal

This step adds live tool-conversation tests on both Responses classes, beyond 004's own: several tool calls, a caller history that already holds tool turns, a pydantic-built async tool, and a streamed conversation with a `json_schema` final answer. The step is test-only (DEC-005-1). It can only run once feature `004.responses-tools` has replaced the interim refusal.

## Source files

none

## Test files

tests/integrations/test_responses_tools_extra.py

## Interface intent

**Library interfaces.** None added or changed.

**Test file.** It uses `tests.integrations.live_support` (step 001) for clients, the recorder, the marker checks and the well-formed-block check. It holds module-local helpers (DEC-005-11):

- the neutral `fetch_record` tool, sync and async forms, which records the ids it was called with;
- its nested tool definition;
- the pydantic model for the typed definition;
- the caller history with prior tool turns;
- the `json_schema` answer format.

## Definition of done

1. [test] (live) Non-streamed `chat_with_tools` asking for records `A` and `B`, on both backends:
   - the tool was called for both ids;
   - the answer is non-empty and holds no reasoning marker.

   (US-030.AC-1, US-057.AC-1, US-058.AC-5, DEC-005-11)
2. [test] (live) The same request streamed with a recorder, on both backends:
   - the tool was called for both ids;
   - the answer is non-empty and contained in the recorder's output;
   - the recorder's output passes the well-formed-block check.

   (US-023.AC-1, US-023.AC-2, US-057.AC-1, DEC-005-11)
3. [test] (live) Non-streamed `chat_with_tools` whose caller history already holds an assistant tool-call turn and its tool-result turn (DEC-005-11), on both backends:
   - the call completes with a non-empty answer;
   - the caller's message list is unchanged.

   (US-057.AC-1, DEC-004-6, DEC-arch-10)
4. [test] (live) Non-streamed `chat_with_tools` with a definition built by `pydantic_to_openai_tool` and a coroutine-function tool, on both backends:
   - the async tool ran at least once;
   - the answer is non-empty.

   (US-031.AC-1, US-030.AC-2, DEC-004-1)
5. [test] (live) Streamed `chat_with_tools` with the `json_schema` answer format and a recorder:
   - the tool ran;
   - the final answer parses as a JSON object holding both required keys;
   - the answer is contained in the recorder's output.

   OpenAI is asserted. The llama-swap variant is marked per DEC-005-9 (US-037.AC-1, US-037.AC-2, US-037.AC-4, DEC-003-10, DEC-005-9).

## Dependencies

001 (shared helper module). Feature `004.responses-tools` delivered: every row of its `status.md` is `done` with verifier PASS. Until then `chat_with_tools` on the Responses classes raises `NotImplementedError` (DEC-003-4), and this step must not be started.
