# Step 002 — Streamed tool-call fragment assembly

## Goal

The shared tool-stream parser assembles each streamed tool request as its own call, with its own name and arguments. This holds when the server omits position numbers and when it repeats the tool name in every fragment.

## Source files

- `llm/llm_client.py`

## Test files

- `tests/test_llm_tools_fragments.py`

## Interface intent

`LLMClient._stream_openai_tools_response` keeps its signature and return shape: the round's content text, plus the list of assembled calls, each shaped as id, type and function name with argument text. Only the way it groups fragments changes, per DEC-002-6:

- **Positioned fragments** — grouped by position as today. A truthy id is set. A non-empty name is set rather than appended. Argument text is appended.
- **Positionless fragments** — matched against the current positionless call. A different call id starts a new call. With no id, a name arriving when the current call already has a name starts a new call. Otherwise the fragment continues the current call.
- **Order** — positioned calls by position, then positionless calls in order of appearance.

Content and reasoning emission, per-round reasoning state (DEC-000-22), and feature 001's error-frame and end-of-stream handling are unchanged.

## Definition of done

1. [test] Positioned fragments that repeat the same tool name in every fragment give one call whose name equals that name exactly once. Its arguments are the concatenation of the argument fragments. — US-035.AC-4
2. [test] Fragments without a position, for two calls with different call ids, give two calls in order of appearance. Each has its own id, name and arguments. — US-035.AC-4
3. [test] Fragments without a position and without ids, where each call's name arrives only in its first fragment, give one call per named fragment. Each call gets the argument fragments that follow its name. — US-035.AC-4
4. [test] Fragments without a position that repeat the same call id and name in every fragment give one call with the name once and the arguments concatenated. — US-035.AC-4
5. [test] Several calls with positions, interleaved by position, are still assembled per position and returned in position order. — US-035.AC-4
6. [test] Every returned call has the shape the tool loop reads: id text (empty when the server sent none), type `function`, and a function with name and argument text. — US-035.AC-4
7. [test] With positionless tool fragments in the stream, the receiver still gets the round's content and its reasoning block, and the returned content excludes the reasoning. — US-027.AC-1, US-027.AC-2
8. [manual/live] The existing live streaming tool suite in `tests/integrations/`, run against llama-swap and OpenAI, still passes. — US-023.AC-1
