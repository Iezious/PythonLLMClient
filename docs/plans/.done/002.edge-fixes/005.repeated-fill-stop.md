# Step 005 — Repeated filling stops when nothing more can be filled

## Goal

Repeated template filling stops after the first pass that changes nothing, instead of running every remaining pass on an unknown or self-referring slot.

This step is deliberately below the 50-line floor, at roughly 10 lines. It is the only change to `llm/llm.py`, and it shares no file or theme with another step, so merging it into one would mix unrelated scopes.

## Source files

- `llm/llm.py`

## Test files

- `tests/test_llm_templates.py`

## Interface intent

`recursive_format_placeholders(text, data)` keeps its signature, its module-only export and its 10-pass cap. The change is that it stops as soon as no slot is found, or as soon as a pass leaves the text unchanged (DEC-002-15). The following behaviour is unchanged:

- Callable values are evaluated per occurrence per pass.
- Values are inserted as their text form.
- A self-referring slot is returned in the text without an error.
- Errors from computed values pass through.

## Definition of done

1. [test] For a template whose remaining slots are all unknown, the known slots are filled, the unknown ones are returned as written, and filling stops after the first pass that changes nothing. Observe this as no further lookups of the data after that pass, for example with a mapping that counts lookups. — US-054.AC-3
2. [test] A computed value whose result refers back to its own slot is computed once. Its slot is returned still in the text, and no error is raised. — US-054.AC-3, US-054.AC-2, US-054.AC-5
3. [test] A value containing another known slot has that slot filled too, across passes. — US-054.AC-1
4. [test] A chain of values that keeps changing the text for more than 10 passes ends after the cap without an error. — US-054.AC-5
5. [test] A computed value whose slot does not appear is not computed. A computed value that fails passes its error through unchanged. — US-055.AC-2, US-055.AC-3
