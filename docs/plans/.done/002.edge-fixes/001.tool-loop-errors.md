# Step 001 — Tool-loop error mapping

## Goal

In `chat_with_tools` on both OpenAI-family clients, four failures change:

- A request for a tool that was not offered ends with the library's error.
- Unreadable arguments end with the library's error.
- An unserialisable result ends with the library's error.
- The round-limit error says that the round limit was the reason and gives its value.

## Source files

- `llm/openai.py`
- `llm/llama_swap.py`

## Test files

- `tests/test_llm_tools_errors.py`

## Interface intent

No public signature changes. The behaviour changes inside `chat_with_tools` of `OpenAIAPIClient` and `LlamaSwapAPIClient`, in each copy separately (DEC-002-1):

- **Offered-tool check** — for each requested call, in order, before its arguments are read. A missing, empty or unadvertised name raises `LLMError`. This holds even when `tools` has a callable under that name (DEC-002-3). The tool is not run.
- **Argument reading** — turns the call's arguments into the keyword mapping the tool is called with:
  - Missing or empty arguments become no arguments.
  - A mapping is used as given.
  - Text is decoded as JSON and must give a JSON object.
  - Anything else raises `LLMError` naming the tool (DEC-002-4).

  The existing argument-name check that raises `ValueError` follows unchanged.
- **Result conversion** — turns a tool's return value into the tool message content. A mapping or list becomes JSON text, and a failed serialisation raises `LLMError` naming the tool (DEC-002-5). Anything else becomes `str()`. This conversion stays outside the wrap that turns a tool's own exception into `RuntimeError`.
- **Round-limit error** — stays `RuntimeError`. Its message states that the round limit was reached, gives the configured value and contains `max_loops` (DEC-002-2).

The coder may extract these as private helpers in each module. That is a file-level choice.

## Definition of done

1. [test] On both clients, streamed and non-streamed, a reply asking for a tool name not advertised in `tools_definitions` ends the call with `LLMError`. This holds even when `tools` maps that name to a callable. The error text contains the requested name, and that callable is not run. — US-035.AC-1
2. [test] On both clients, a requested call with an empty or missing tool name ends with `LLMError`, and no tool runs. — US-035.AC-1
3. [test] On both clients, argument text that is not valid JSON ends with `LLMError` whose text names the tool, and the tool does not run. — US-035.AC-2
4. [test] On both clients, argument text that decodes to a JSON value other than an object ends with `LLMError` naming the tool, and the tool does not run. The values to cover are a list, a number, a string and `null`. — US-035.AC-2
5. [test] On both clients, the tool runs with the arguments the model gave when they arrive as JSON object text or as a mapping. It runs with no arguments when they are empty or missing. — US-030.AC-1
6. [test] On both clients, a tool returning a mapping or list that cannot be serialised to JSON ends with `LLMError` naming the tool. Any other non-text result, such as an object with a custom text form, is still sent as its text form. — US-035.AC-3
7. [test] On both clients, a tool returning a serialisable mapping or list has its result sent to the model in the next round as JSON text, with non-ASCII characters kept unescaped. — US-030.AC-1
8. [test] On both clients, reaching the round limit ends the call with `RuntimeError`. The message says the round limit was the reason, contains `max_loops` and contains the configured limit value. No partial answer is returned. — US-034.AC-3, US-034.AC-2
9. [test] On both clients, a round limit set for one call is honoured: with a limit of 2 and a model that keeps asking for tools, exactly 2 requests are sent before the error. — US-034.AC-4, US-034.AC-1
10. [test] On both clients, existing failure kinds are unchanged:
    - A tool that raises ends with `RuntimeError` naming the tool.
    - An argument name the callable lacks ends with `ValueError`, and the tool does not run.
    - An advertised tool without a callable is refused with `ValueError` before any request.

    — US-033.AC-1, US-033.AC-2, US-033.AC-4, US-032.AC-1
11. [manual/live] The existing live tool suites in `tests/integrations/`, run against llama-swap and OpenAI, still pass. — US-030.AC-1
