# Step 002 — Request errors: transport failures and the streamed-request helper

## Goal

Map connection failures and timeouts on every non-streamed request to the library error carrying the address, and add one base helper that opens a streamed request and turns a refused stream (non-2xx) or a transport failure into the library error with the server's reply.

## Source files

llm/llm_client.py

## Test files

tests/test_llm_request_errors.py

## Interface intent

- **`LLMClient._request`** (changed): same inputs (method, path, request keywords) and outputs (decoded JSON or raw bytes for a 2xx reply). Additionally, a transport failure while connecting, sending or reading the body (connection error, server disconnect, payload error, timeout) raises `LLMError` per DEC-001-7. The non-2xx mapping is unchanged (DEC-000-11). Only `_request` and the new helper change in this step; `_iter_sse_data` and the parsers are step 003's.
- **`LLMClient._stream_post`** (new, DEC-001-8): an async context manager. Inputs: a path under the base address and a JSON payload. It ensures the session, adds the bearer header only when the client holds a token, applies the client's total time limit, and posts. On a 2xx reply it yields the open response for the caller to read; the response is released when the block exits. On a non-2xx reply it reads the reply body and raises `LLMError` carrying the address, the status and the server's reply (DEC-arch-5, format of DEC-000-11). A transport failure while opening raises `LLMError` per DEC-001-7. Exceptions raised by the caller's block pass through unchanged.

## Definition of done

1. [test] A connection failure in `_request` raises `LLMError` whose text carries the request address (US-011.AC-3, DEC-001-7).
2. [test] A timeout in `_request` raises `LLMError` whose text carries the request address (US-011.AC-3, DEC-001-7).
3. [test] A failure while reading a 2xx body in `_request` (payload error / disconnect) raises `LLMError` (US-011.AC-3, DEC-001-7).
4. [test] With a credential set on the client, no transport `LLMError` text (message or description) contains the credential value or the phrase "status " followed by a number (US-011.AC-4, DEC-001-7).
5. [test] A non-2xx reply in `_request` still raises `LLMError` with message "Request to <url> failed with status <n>" and the reply text as description (US-011.AC-2, DEC-000-11).
6. [test] `_stream_post` on a non-2xx reply raises `LLMError` whose text carries the address, the status and the server's reply text, and not the credential (US-011.AC-1, US-011.AC-4, DEC-arch-5, DEC-001-8).
7. [test] `_stream_post` on a 2xx reply yields the response; the request goes to base address + path with the JSON payload, carries `Authorization: Bearer <token>` when the client has a token and no such header when it has none, and is bounded by the client's time limit (US-005.AC-2, DEC-001-8).
8. [test] A connection failure or timeout while `_stream_post` opens the request raises `LLMError` carrying the address (US-011.AC-3, DEC-001-7).
9. [test] An exception raised inside the caller's `_stream_post` block (e.g. a receiver failure) reaches the caller unchanged — same type, same object (US-022.AC-2, DEC-000-23).
10. [test] On the deprecated Ollama client, a transport failure during `embed_batch` raises `LLMError` and makes no fallback per-text request; a 404 reply still triggers the fallback (DEC-000-42, DEC-001-7).
11. [test] The existing unit suite passes unchanged (`tests/test_llm_embeddings.py`, `tests/test_get_models.py`, `tests/test_llm_tools_streaming.py`, `tests/test_llm_tools_reasoning_stream.py`).
