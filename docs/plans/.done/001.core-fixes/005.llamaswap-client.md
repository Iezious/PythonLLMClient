# Step 005 — llama-swap client: streamed errors, empty content, settings

## Goal

Apply the same client-level fixes to the llama-swap client (a separate copy, DEC-000-35): its streamed requests go through the base helper, a reply with no content is empty text, and only the settings the app set — including stop sequences, token bias, end-user id and response format — reach the server. Its credential stays optional.

## Source files

llm/llama_swap.py

## Test files

tests/test_llamaswap_client_fixes.py

## Interface intent

- **Supported-settings and alias tables** (changed): no built-in values (DEC-001-13); stop sequences, token bias, end-user id and response format added (DEC-001-14). Alias table unchanged.
- **`_merge_options`** (unchanged logic): base merge, `reasoning_effort` still dropped, the thinking switch sent as-is only when set (DEC-000-19).
- **`chat`** (changed): the streamed branch opens its request through the base streamed-request helper (DEC-001-8), keeping the trace wrapper rule (DEC-000-48); the non-streamed branch returns empty text for null content (DEC-001-12).
- **`chat_json`** (changed): empty text for null content (DEC-001-12); the response-format setting, when set, is sent instead of the JSON-object format (DEC-001-2).
- **`chat_with_tools`** (changed): null content of the final answer and of the recorded assistant tool-call turn becomes empty text (DEC-001-12); the response-format parameter wins over the setting (DEC-001-15).
- **`_tools_stream_request`** (changed, seam kept): same inputs and outputs; opens its request through the base streamed-request helper (DEC-001-8).
- **Constructor** and **`embed_batch`**: unchanged (credential optional, US-005; DEC-001-16).

## Definition of done

1. [test] A llama-swap client with a credential sends `Authorization: Bearer <credential>` on a streamed request; without one it sends no such header and the call works (US-005.AC-1, US-005.AC-2).
2. [test] A streamed `chat` that gets a non-2xx reply raises `LLMError` carrying the address, the status and the server's reply, and not the credential (US-011.AC-1, US-011.AC-4, DEC-arch-5).
3. [test] A streamed tool round (`_tools_stream_request`) that gets a non-2xx reply raises the same kind of `LLMError` (US-011.AC-1, DEC-arch-5).
4. [test] A streamed `chat` against an unreachable server raises `LLMError` (US-011.AC-3, DEC-001-7).
5. [test] A streamed `chat` through the helper still gives the receiver every piece in order and returns their concatenation (US-008.AC-1, US-021.AC-2).
6. [test] Non-streamed `chat` and `generate` with null reply content return empty text (US-009.AC-1, DEC-001-12).
7. [test] With tracing switched on, a non-streamed `chat` with null reply content returns empty text (US-009.AC-3, DEC-001-12).
8. [test] `chat_json` with null reply content returns empty text; `chat_with_tools` with a null final answer returns empty text; a tool-call turn with null content enters the next round's conversation with empty text (US-009.AC-1, DEC-001-12).
9. [test] With no settings from the app, the request body of `chat`, `chat_json` and `chat_with_tools` carries no generation setting (no temperature, top-p, penalties, max tokens, seed, thinking switch) (US-018.AC-1, DEC-001-13).
10. [test] Stop sequences, token bias, end-user id and response format set by the app — as client defaults or per call — appear in the request body of `chat`, `generate` and `chat_with_tools` (US-019.AC-1, DEC-001-14).
11. [test] `chat_json` sends the app's response-format setting when one is set and the JSON-object format otherwise (DEC-001-2).
12. [test] In `chat_with_tools` the response-format parameter is sent when given, even if a response-format setting is set; the setting is sent when the parameter is absent (DEC-001-15).
13. [test] Existing merge rules hold: a per-call `None` removes a client default; `context_length` acts as `max_tokens`; an unknown setting is not sent; a per-call value wins over a client default (US-014.AC-2, US-015.AC-1, US-016.AC-2, US-017.AC-1, US-017.AC-2).
14. [test] Thinking on is sent as the thinking switch; `reasoning_effort` is never sent; thinking unset sends neither (US-025.AC-1, DEC-000-19).
15. [test] `embed_batch` sends the call's end-user id over the client's, the client's when the call has none, and no generation setting (US-041.AC-3, US-041.AC-4, DEC-001-16).
16. [test] The existing llama-swap unit tests (`tests/test_llm_tools_streaming.py`, `tests/test_llm_embeddings.py`, `tests/test_get_models.py`) pass unchanged.
