# Step 001 — OpenAI Responses class: non-streamed tool conversation

## Goal

`chat_with_tools` on `OpenAIAPIClient` runs the tool loop on Responses (non-streamed): tools flattened, calls and results sent as items, each round's reasoning carried to later rounds of the call, 002's tool-loop rules reproduced; this replaces the interim refusal (DEC-003-4). Unavoidable cohesion: the loop, its item conversion and its round reading only work together, so they land in one step (≈170–200 LoC).

## Interface intent

- **Tool flattening** (new private helper): input the app's tool definitions; output the Responses tool list (DEC-004-5, DEC-004-1). Also the source of the advertised tool names for the pre-flight and offered checks, reading either shape.
- **Round-input conversion** (new private helper): inputs the internal copy of the conversation and the per-call reasoning record; output the `input` item list for one round (DEC-004-6, DEC-004-7, DEC-004-4). Caller-style turns go through 003's existing message-item conversion.
- **Non-streamed round reading** (new private helper): input a non-streamed reply; output the round text, the round's tool calls (dense, in order) and its reasoning items, or `LLMError` for a failed / incomplete reply (DEC-004-8).
- **Argument reading and result conversion** (private helpers, the coder's choice whether separate): this module's own copies of 002's rules (DEC-002-4, DEC-002-5); copied from the chat-completions module, not imported.
- **`chat_with_tools`** (rewritten; signature unchanged): pre-flight, settings merge, internal copy with the system instruction at the head, per-round body (DEC-004-10) sent through `_request`, round reading, tool runs per DEC-004-11, reasoning record per DEC-004-7, round limit, trace per DEC-004-10. Returns the final round text. `stream=True` is step 002's; this step need not make it work.
- **Payload builder, response-format translation, `_merge_options`** (003's): reused; changed only if a small extension is needed to add `tools` and the round's `input` (coder's choice), without changing what `chat`, `generate` and `chat_json` send.

## Definition of done

1. [test] Each nested tool definition is sent flattened — type function, name, description and parameters only when present, `strict` copied when the app gave it and `false` otherwise; a definition already flat is sent unchanged; order kept; the app's definitions are unchanged after the call; a definition built by `pydantic_to_openai_tool` is accepted (DEC-004-5, DEC-004-1, US-031.AC-1).
2. [test] Every round is one `POST /responses` whose body holds exactly the keys of DEC-003-11 for the settings given, plus `tools`; `stream` is false; the reasoning setting for thinking on is sent on every round; there is no request to `/chat/completions` (DEC-004-10, DEC-003-9, US-056.AC-4).
3. [test] The `response_format` parameter is sent as the translated text format on every round, tool-call rounds included; it wins over a response-format setting; the setting is used when no parameter is given; with neither there is no `text` field (US-037.AC-3, DEC-001-15, DEC-003-10, DEC-004-10).
4. [test] A first-round reply without function-call items returns that round's text; no tool runs; exactly one request is sent (US-030.AC-3, DEC-004-8).
5. [test] A reply with a function call runs the tool with the decoded arguments; the next request's input is the caller's items, then that round's reasoning items exactly as received, then `{type: function_call, call_id, name, arguments}`, then `{type: function_call_output, call_id, output}` with the result text; the final round's text is returned (US-030.AC-1, US-058.AC-3, DEC-arch-9, DEC-004-6, DEC-004-7).
6. [test] A tool round with non-empty text alongside its calls sends `{type: message, role: assistant, content: <text>}` between that round's reasoning and its function calls; a round with empty or null text sends no assistant item (DEC-004-4, DEC-004-6, DEC-004-8).
7. [test] Two function calls in one reply (behind a reasoning item) run in their order of appearance, sequentially; the next input holds both function calls in that order followed by both outputs, each output carrying its call's `call_id` (DEC-arch-10, DEC-004-8, US-030.AC-1).
8. [test] Over three rounds, round 1's reasoning is re-sent on rounds 2 and 3 ahead of round 1's calls and round 2's reasoning on round 3 ahead of round 2's calls; a reasoning item with empty encrypted content and plain reasoning text is re-sent unchanged; the final round's reasoning is not sent anywhere (US-058.AC-3, DEC-004-7).
9. [test] After the call the caller's message list equals its prior contents; the returned answer holds no reasoning text and no `<think>` / `</think>` marker (US-058.AC-4, US-058.AC-5, US-028.AC-1).
10. [test] A caller history that already holds an assistant tool-call turn and its tool-result turn is sent as function-call and function-call-output items, without any reasoning item (DEC-004-6).
11. [test] An awaitable tool is awaited and its result sent; a tool returning a mapping or list is sent as JSON text with non-ASCII kept; any other result as its text form; the output field is always text (US-030.AC-2, US-030.AC-1, DEC-002-5).
12. [test] An advertised tool without a callable (nested or flat definition) is refused with `ValueError` before any request (US-032.AC-1, DEC-004-5).
13. [test] A call naming a tool not advertised — even when `tools` holds a callable under that name — or a call with an empty or missing name ends with `LLMError` naming the tool (or saying the name was empty), and that callable does not run (US-035.AC-1, DEC-002-3).
14. [test] Argument text that is not JSON, or JSON that is not an object (a list, a number, a string, null), ends with `LLMError` naming the tool and the tool does not run; empty or missing arguments run the tool with no arguments (US-035.AC-2, US-030.AC-1, DEC-002-4).
15. [test] An argument name the callable lacks ends with `ValueError` and the tool does not run; a tool that raises ends with `RuntimeError` naming the tool and no further request is sent; an unserialisable mapping result ends with `LLMError` naming the tool (US-033.AC-1, US-033.AC-2, US-033.AC-3, US-033.AC-4, US-035.AC-3, DEC-004-11).
16. [test] With a round limit of 2 and a model that keeps asking for tools, exactly 2 requests are sent, then `RuntimeError` whose text contains `max_loops` and `2`; no answer is returned (US-034.AC-1, US-034.AC-2, US-034.AC-3, US-034.AC-4, DEC-002-2).
17. [test] A round reply with status failed or incomplete ends with `LLMError` carrying the server's reason, also on a second round; a non-2xx reply ends with `LLMError` carrying the address and the server's reply and not the credential (US-060.AC-1, US-060.AC-4, DEC-004-8, DEC-003-12).
18. [test] A no-counterpart setting is absent from every round's body and emits one `LLMSettingIgnoredWarning` for the client; a second tool call on the same client, or a `chat` after a tool call, emits none for that setting (US-061.AC-1, US-061.AC-2, DEC-004-12).
19. [test] With tracing enabled the call returns the same answer, and its record shows the request of each round tagged with its round number on `/responses`, each tool call with its arguments, each tool result, and the final answer (US-049.AC-4, US-049.AC-12, US-049.AC-5, US-050.AC-4, DEC-004-10).
20. [test] `chat_with_tools` no longer raises `NotImplementedError`; 003's refusal test is gone from `tests/test_openai_responses_request.py` and every other test in that file still passes (DEC-003-4 replaced, US-057.AC-1).
