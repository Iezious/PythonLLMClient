# Step 003 — llama-swap Responses class: non-streamed tool conversation

## Goal

`chat_with_tools` on `LlamaSwapAPIClient` runs the tool loop on Responses, non-streamed, as its own copy of the logic (DEC-arch-2):

- tools are flattened;
- calls and results are sent as typed items;
- each round's reasoning, including items with plain reasoning text and empty encrypted content, is carried to later rounds of the call;
- 002's tool-loop rules are reproduced.

This replaces the interim refusal (DEC-003-4). Unavoidable cohesion, as in step 001 (about 170–200 LoC).

## Definition of done

1. [test] Each nested tool definition is sent flattened:
   - type function;
   - name;
   - description and parameters only when present;
   - `strict` copied when given, `false` otherwise.

   A flat definition is sent unchanged, order is kept, and the app's definitions are unchanged after the call. A `pydantic_to_openai_tool` definition is accepted (DEC-004-5, DEC-004-1, US-031.AC-1).
2. [test] Every round is one `POST /responses` whose body holds exactly the keys of DEC-003-11 for the settings given, plus `tools`, with `stream` false. Thinking on sends the reasoning effort without a summary on every round. No request goes to `/chat/completions`. Built without a credential, the rounds carry no bearer header (DEC-004-10, DEC-003-2, US-056.AC-4, US-005.AC-2).
3. [test] The `response_format` parameter is sent as the translated text format on every round, tool-call rounds included.
   - The parameter wins over a response-format setting.
   - The setting is used when no parameter is given.
   - With neither, the body has no `text` field.

   (US-037.AC-3, DEC-001-15, DEC-003-10, DEC-004-10)
4. [test] A first-round reply without function-call items returns that round's text. No tool runs and exactly one request is sent (US-030.AC-3, DEC-004-8).
5. [test] A reply with a function call runs the tool with the decoded arguments, and the final round's text is returned. The next request's input is, in order:
   1. the caller's items;
   2. that round's reasoning item exactly as received (plain reasoning text, empty `summary`, empty `encrypted_content`);
   3. `{type: function_call, call_id, name, arguments}`;
   4. `{type: function_call_output, call_id, output}`, with the result text.

   (US-030.AC-1, US-058.AC-3, DEC-arch-9, DEC-004-6, DEC-004-7)
6. [test] A tool round with non-empty text alongside its calls sends `{type: message, role: assistant, content: <text>}` between that round's reasoning and its calls. A round with empty or null text sends no assistant item. No assistant item is ever sent without its type (DEC-004-4, DEC-004-6).
7. [test] Two function calls in one reply, behind a reasoning item, run in their order of appearance. The next input holds both calls in order followed by both outputs, each carrying its own `call_id` (DEC-arch-10, DEC-004-8, US-030.AC-1).
8. [test] Over three rounds, each round's reasoning is re-sent on every later round ahead of that round's calls. The final round's reasoning is not sent anywhere (US-058.AC-3, DEC-004-7).
9. [test] After the call, the caller's message list equals its prior contents. The returned answer holds no reasoning text and no marker (US-058.AC-4, US-058.AC-5, US-028.AC-1).
10. [test] A caller history that already holds an assistant tool-call turn and its tool-result turn is sent as function-call and function-call-output items (DEC-004-6).
11. [test] Tool runs and results:
    - An awaitable tool is awaited.
    - A mapping or list result is sent as JSON text with non-ASCII kept.
    - Any other result is sent as its text form.
    - The output field is always text.

    (US-030.AC-2, US-030.AC-1, DEC-002-5)
12. [test] An advertised tool without a callable, in nested or flat form, is refused with `ValueError` before any request (US-032.AC-1, DEC-004-5).
13. [test] A call naming a tool that was not advertised ends with `LLMError` naming the tool, even when `tools` holds a callable under that name. A call with an empty or missing name also ends with `LLMError`. That callable does not run (US-035.AC-1, DEC-002-3).
14. [test] Argument text that is not JSON, or JSON that is not an object, ends with `LLMError` naming the tool, and the tool does not run. Empty or missing arguments run the tool with no arguments (US-035.AC-2, US-030.AC-1, DEC-002-4).
15. [test] Other tool failures:
    - An argument name the callable lacks ends with `ValueError`, and the tool does not run.
    - A tool that raises ends with `RuntimeError` naming the tool, and no further request is sent.
    - An unserialisable result ends with `LLMError` naming the tool.

    (US-033.AC-1, US-033.AC-2, US-033.AC-3, US-033.AC-4, US-035.AC-3, DEC-004-11)
16. [test] With a round limit of 2 and a model that keeps asking for tools, exactly 2 requests are sent. The call then ends with `RuntimeError` whose text contains `max_loops` and `2`, and no answer is returned (US-034.AC-1, US-034.AC-2, US-034.AC-3, US-034.AC-4, DEC-002-2).
17. [test] A round reply with status failed or incomplete ends with `LLMError` carrying the server's reason. A non-2xx reply (for example a 404 with a JSON error body) ends with `LLMError` carrying the address and the server's reply (US-060.AC-1, DEC-004-8, DEC-003-12).
18. [test] A setting with no Responses counterpart is absent from every round's body and emits one `LLMSettingIgnoredWarning` per client. A second tool call, or a `chat` after a tool call, emits none for that setting (US-061.AC-1, US-061.AC-2, DEC-004-12).
19. [test] With tracing enabled, the call returns the same answer. Its record shows:
    - each round's request on `/responses`, tagged with its round number;
    - each tool call with its arguments;
    - each tool result;
    - the final answer.

    (US-049.AC-4, US-049.AC-12, US-049.AC-5, US-050.AC-4, DEC-004-10)
20. [test] `chat_with_tools` no longer raises `NotImplementedError`. 003's refusal test is gone from `tests/test_llamaswap_responses_request.py`, and every other test in that file still passes (DEC-003-4 replaced, US-057.AC-1).
