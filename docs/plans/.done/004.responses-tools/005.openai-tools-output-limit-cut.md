# Step 005 — OpenAI Responses tool conversation: a round cut at the app's own output limit

## Goal

On `OpenAIAPIClient`, a tool round that the server stops at the output limit the app set is the answer when it holds no tool call, and ends the call with `LLMError` when it holds one, streamed and not. Every other early end of a round stays an error (DEC-arch-13, tool part). The step is below the 50-line budget. It is kept apart from step 006 because the two steps touch different files and depend on different 003 steps.

## Interface intent

- **Non-streamed tool-round reader** (module-level, changed): gains the keyword-only output-limit flag of DEC-004-15 (default off). Input: the reply and the flag. Output: the round (text, tool calls, carry items) as today. With the flag on and a cut at the app's limit (DEC-003-18), it returns the round's text with no tool calls when the reply holds no tool call. It raises `LLMError` carrying the server's reason when the reply holds any tool call (DEC-004-16). Otherwise its behaviour is unchanged (DEC-004-8).
- **Tool-round stream parser** (private method, changed): gains the same keyword-only flag (default off). Inputs: the open streamed response, the optional receiver and the flag. Output: the round, as today. With the flag on, a matching incomplete event ends the round as the completed event does when no tool call has started in the round. If a call has started, the event raises `LLMError` with the reason and delivers no further piece (DEC-004-17). Otherwise unchanged (DEC-004-9).
- **`chat_with_tools`** (changed body, signature unchanged): computes the flag once per call from its wire settings and passes it to the reader or the parser on every round (DEC-004-15). The loop's branches are unchanged: no tool calls means the round text is the answer (DEC-004-18).
- Docstrings of the reader, the parser and `chat_with_tools` state the new rule: a cut at the app's limit is the answer when the round has no calls and an error when it has calls; with no app limit, and for every other early end, the round still raises.

## Definition of done

1. [test] Non-streamed, with `max_tokens` given as a call option: a first round cut at the app's limit, holding answer text and no tool call, makes `chat_with_tools` return that text, extracted exactly as from a completed round with the same output. No further request is sent and no tool runs (US-062.AC-4, DEC-004-16).
2. [test] Non-streamed: after a first round whose tool ran, a second round cut at the app's limit with no tool call returns the second round's text. The first round's tool ran exactly once (US-062.AC-4, DEC-004-16, DEC-004-18).
3. [test] DoD-1 also holds, streamed and not, when the limit comes from the client's default settings, and when it is given through the `context_length` alias, either as a call option or as a default (US-062.AC-4, DEC-004-15, DEC-003-17).
4. [test] Non-streamed, with the app's limit set: a round cut at the app's limit that holds one or more tool calls ends the call with `LLMError` carrying the server's reason. No tool of that round runs and no further request is sent. This is checked on the first round and on a later round; in the later-round case, earlier rounds' tools ran exactly once (US-062.AC-4, DEC-004-16, DEC-004-18).
5. [test] Streamed, with the app's limit set: a round cut at the app's limit in which no tool call has started (first round and later round) returns that round's text deltas joined, with no markers and no reasoning. The receiver got every piece of every round in order. A reasoning block still open at the event is closed by a closing-marker piece of its own, and nothing after the event is delivered (US-062.AC-4, US-027.AC-1, DEC-004-17, DEC-000-20).
6. [test] Streamed, with the app's limit set: a round cut at the app's limit in which a tool call has started ends with `LLMError` carrying the server's reason. This holds both for a call item that was added and for an arguments fragment alone. No piece is delivered after the event, not even a closing marker. No tool of that round runs and no further request is sent; in a later round, earlier rounds' tools ran exactly once (US-062.AC-4, DEC-004-17, DEC-004-18).
7. [test] With no app limit (never set, or a default limit cleared per call with `None`), a round cut for the output limit ends with `LLMError` carrying the server's reason, streamed and not, with and without tool calls in the round. No tool of that round runs (US-062.AC-6, DEC-004-15, DEC-003-17).
8. [test] With the app's limit set, each of the following still ends with `LLMError`, streamed and not: an incomplete round whose reason is any other value, has no reason, or has no incomplete details; a failed reply or failed event; an error event; and a stream that ends without a completion event (US-024.AC-2, DEC-003-18, DEC-004-8, DEC-004-9).
9. [test] The reader and the parser called without the flag (its default) treat a cut round as before: `LLMError` with the reason (DEC-004-15).
10. [test] With `max_loops` 1 and the app's limit set, a first round cut at the app's limit with no tool call returns its text and raises no round-limit error (DEC-004-18, DEC-002-2).
11. [test] With tracing enabled, a cut answer round is returned and recorded as the call's response, as a completed answer round is (DEC-004-18, DEC-004-10, DEC-000-48).
12. [test] The existing unit suite passes with no existing test file edited, including the tests named in `005.context.md`, which cover the no-limit case (US-062.AC-6, DEC-004-15).
13. [manual/live] The docstrings of every changed function state the new rule and cite DEC-arch-13 / DEC-004-16 / DEC-004-17. The verifier checks this in its documentation review; there is no automated test.
14. [manual/live] The live check of a cut tool round on OpenAI lands in feature 005, which is revised in a separate pass. It is not in this step's test files.
