## Touch site (before feature 001; feature 001 does not edit this file)

`llm/trace.py` is 154 lines:

- **`TraceSession(f, model, operation, timestamp)`** writes the header in `__init__`.
  - `_write` writes and then flushes.
  - `log_system` skips only `None`.
  - `log_messages` writes the `MESSAGE HISTORY` section: `[role] content` lines plus `-> tool_call:` lines.
  - The other logging methods are `log_request`, `log_response`, `log_chunk`, `log_tool_call`, `log_tool_result` and `log_error`.
  - `close()` writes `END TRACE`.
- **`LLMTracer.__init__`** reads `LLM_TRACE` (`1`, `true` or `on`) and `LLM_TRACE_FOLDER`.
- **`trace(operation, model)`** is a `@contextmanager`:
  1. When disabled, it yields `_NOOP_SESSION`.
  2. It takes `now = datetime.now(timezone.utc)`.
  3. It calls `date_dir.mkdir(parents=True, exist_ok=True)`, unguarded.
  4. It builds the filename `llm-trace-{now:%Y%m%d-%H%M%S%f}.log`.
  5. It opens the file with `f = open(filepath, "w", encoding="utf-8")`, unguarded and truncating.
  6. It runs `try: yield session except Exception as exc: session.log_error(exc); raise finally: session.close(); f.close()`.
- **`_NoopSession`** has every method as a no-op. `_format_json` is already safe.

## Gotchas

- When the date-folder path is an existing file, `mkdir(..., exist_ok=True)` raises `FileExistsError`, which is an `OSError`. The folder guard must treat it as a setup failure. It is not a name collision: only `FileExistsError` from the exclusive `open` triggers the counter suffix.
- After a setup failure, the generator must still yield exactly once, the no-op session, so that the caller's body runs. Exceptions from the body must propagate unchanged through that branch.
- The guards around `log_error` and `close()` must catch `Exception` only. `CancelledError` is a `BaseException` and must keep its current path: no error section, footer attempted, file closed.
- **Instruction recognition (DEC-002-14).**
  - Every client inserts `{"role": "system", "content": system}` at index 0 of a copy of the messages, and only when `system` is truthy. It then calls `t.log_system(system)` followed by `t.log_messages(msgs)`.
  - Call sites: `llm/openai.py` `chat` / `chat_json` / `chat_with_tools`, the same in `llm/llama_swap.py`, and `llm/ollama.py` `chat` / `chat_json` / `chat_with_tools`.
  - None of these call sites is edited. The session remembers the logged instruction and compares the first message against it.
  - The `llm/AGENTS.md` convention "log_system → log_messages" stays true.
