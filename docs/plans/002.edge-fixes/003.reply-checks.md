# Step 003 — Embedding, model-list and JSON-only reply checks

## Goal

On both OpenAI-family clients:

- An embedding batch returns exactly one vector per text, in the texts' order, or the library's error.
- A malformed or unreadable embedding reply or model list ends with the library's error.
- `chat_json` on OpenAI no longer misreports a valid single JSON value.

## Source files

- `llm/openai.py`
- `llm/llama_swap.py`

## Test files

- `tests/test_llm_embeddings_checks.py`
- `tests/test_llm_models_checks.py`

## Interface intent

No public signature changes. Behaviour changes inside these methods of `OpenAIAPIClient` and `LlamaSwapAPIClient`, each copy separately (DEC-002-1):

- **`embed_batch`** — checks the reply and returns the vectors in text order (DEC-002-8):
  - The reply must be a mapping with a list of entries.
  - Each entry must be a mapping holding a non-empty vector list.
  - The count must equal the number of texts.
  - When every entry carries an integer position, the positions must be exactly 0..n-1 and are used for ordering. Otherwise server order is kept.
  - Any violation raises `LLMError`.
  - The checks run inside the trace session, before the response count is recorded.
- **`list_models`** — checks the reply as a mapping with a list of entries, each a mapping with a non-empty string id, and returns the ids in server order (DEC-002-9).
- **`get_models`** — applies the same checks and returns the entries unchanged (DEC-002-9).
- **All three** map an unreadable successful body to `LLMError` at the call site (DEC-002-10). That covers a JSON decode failure raised by the shared request helper and a non-JSON body returned as bytes. Library errors from the helper (non-2xx, transport) pass through unchanged. The shared request helper is not edited.
- **`chat_json` (OpenAI)** — the no-op loop over the expected shape's fields is removed, so the check is only the JSON parse (DEC-002-7). On llama-swap, only confirm that no such loop exists.

The coder may add private helpers per module for the shared checks; that is a file-level choice.

## Definition of done

Embeddings, on both clients:

1. [test] For n texts and a reply of n well-formed entries, `embed_batch` returns exactly n vectors. — US-042.AC-2
2. [test] When the reply's entries carry positions out of order, the vectors come back in the texts' order. — US-042.AC-5
3. [test] When the reply's entries carry no positions, the vectors come back in the reply's order. — US-042.AC-2
4. [test] A reply with fewer or more entries than texts ends with `LLMError`. — US-042.AC-3
5. [test] Positions that are not exactly 0..n-1 end with `LLMError`. This covers a duplicate, a gap and an out-of-range value. — US-042.AC-5
6. [test] Each of these ends with `LLMError`: an entry that is not a mapping, an entry without a vector, a vector that is not a list, and an empty vector. — US-043.AC-3
7. [test] Each of these ends with `LLMError`: a reply that is not a mapping, and a reply whose entry list is missing or not a list. — US-043.AC-2, US-043.AC-4
8. [test] A successful reply whose body is not JSON (bytes), or whose decoding raises a JSON decode error, ends with `LLMError`. — US-043.AC-4
9. [test] A refusal raised by the request helper as `LLMError` reaches the caller unchanged, with the same message and description. — US-043.AC-1
10. [test] `embed` returns the single vector for one text, and ends with `LLMError` when the reply holds no vector. — US-041.AC-1, US-041.AC-2

Model listing, on both clients:

11. [test] `list_models` returns the ids in the server's order, and `get_models` returns the entries exactly as sent. — US-044.AC-1, US-045.AC-1
12. [test] Each of these ends with `LLMError`, from both `list_models` and `get_models`: an entry that is not a mapping, an entry without an id, an id that is not text, and an empty id. — US-046.AC-2
13. [test] Each of these ends with `LLMError` from both methods: a reply that is not a mapping, and a reply whose entry list is missing or not a list. — US-046.AC-1
14. [test] A successful reply whose body is not JSON (bytes), or whose decoding raises a JSON decode error, ends with `LLMError` from both methods. — US-046.AC-3

JSON-only answer:

15. [test] On OpenAI, with an expected shape that has fields without defaults, a reply that is a valid single JSON value is returned unchanged. The values to cover are a number, `true`, `null`, a string and a list. The same holds on llama-swap. — US-039.AC-3
16. [test] On both clients, with an expected shape, a reply that is not JSON ends with `LLMError`. Without an expected shape, the same reply is returned. — US-039.AC-1, US-039.AC-2

Live:

17. [manual/live] The existing live embedding and model-listing tests in `tests/integrations/`, run against llama-swap and OpenAI, still pass, and `embed_batch` returns one vector per text. — US-042.AC-2
