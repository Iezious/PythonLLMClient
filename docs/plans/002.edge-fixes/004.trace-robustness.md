# Step 004 — Tracing never changes the outcome; own records; instruction once

## Goal

Make the tracer safe for the calls it records:

- A record that cannot be set up leaves the call untraced.
- A record-write failure never replaces the call's result or error, and never leaks the file.
- Calls starting at the same instant get separate complete records.
- The system instruction appears once among the record's conversation sections.

## Interface intent

The public shape of `LLMTracer` (constructor, `enabled`, `trace(operation, model)`) and of the session's logging methods is unchanged.

- **`LLMTracer.trace`**:
  - A failure (`OSError`) while creating the date folder or opening the record yields the shared no-op session (DEC-002-11).
  - The record is created exclusively. When the name is already taken, a counter suffix is added, `-1`, `-2` and so on, up to the bound (DEC-002-13).
  - Recording the caller's error and writing the footer are each guarded, and the file is closed in every case. The caller's own exception is re-raised unchanged (DEC-002-12).
  - Only the setup is guarded: an exception from the caller's body is never taken as a setup failure.
- **`TraceSession`**:
  - Its internal writer marks the session broken on the first write failure (any `Exception`) and skips every later write. This also covers the header write in its constructor (DEC-002-12).
  - `log_messages` skips a leading system-role message whose text equals the non-empty instruction this session logged through `log_system`. Every other message is written (DEC-002-14).
- **Test seams** — the session time comes from the module-level `datetime` name, and the record file is opened through the builtin `open` looked up in the module (DEC-002-16).

## Definition of done

1. [test] With tracing on and the trace folder unusable, a call made through a client returns its normal result and leaves no record. "Unusable" covers two cases: the folder path names an existing file, so the date folder cannot be created; and opening the record fails with an `OSError`. — US-050.AC-2
2. [test] With tracing on, when record writes start failing during a successful call, the call returns its normal result without raising, and the record file is closed. — US-050.AC-3
3. [test] With tracing on, when a call fails and writing the record fails while the error is recorded, the app receives the call's own error: same type and same text. The record file is closed. — US-050.AC-3
4. [test] With tracing on, when only the footer write fails, the app still receives the call's own result on success and its own error on failure. — US-050.AC-3
5. [test] With tracing on and writes working, a failing call's record ends with the error section followed by the end marker, and the app receives the same error as with tracing off. — US-050.AC-1, US-050.AC-4
6. [test] A cancelled traced call propagates the cancellation unchanged. Its record has no error section and still ends with the end marker. — US-050.AC-4
7. [test] With the clock frozen to one instant, two trace sessions that overlap (nested or concurrent) produce two distinct record files. Each holds its own complete record: header, its own logged content, and the end marker. — US-051.AC-1
8. [test] A record with no name collision keeps the documented layout: one file under the UTC date folder, named with the timestamp and no suffix. — US-048.AC-1
9. [test] With tracing off, or with no folder set, no record appears. — US-048.AC-2
10. [test] For a traced `chat` on OpenAI and on llama-swap with a non-empty system instruction:
    - The instruction text appears in the system-prompt section.
    - The message-history section does not repeat it.
    - The caller's own messages, including a system message of the caller's own, appear in the history.

    — US-049.AC-6, US-049.AC-2, US-049.AC-10
11. [test] For a traced `chat_json` and a traced `chat_with_tools` on OpenAI and llama-swap with a non-empty system instruction, the message-history section does not repeat the instruction. — US-049.AC-6
12. [test] For a traced call without a system instruction, a caller's leading system message is written in the history. — US-049.AC-10
13. [test] For a traced call with a system instruction, the request section still shows the payload as sent, including the instruction message. — US-049.AC-11
14. [test] An app using `LLMTracer` directly with an operation label of its own still gets a record of the same kind. — US-052.AC-1
