# Step 002 — Settings and answer formats on Responses

## Goal

This step adds live tests on both Responses classes for the following:

- a reply cut at the token cap the app set is returned as text, with no error and no notice, in `chat` and `generate`, streamed and not, with the cap given per call or as a client default (US-062, DEC-arch-13);
- a setting with no Responses counterpart is dropped with one warning per client;
- `json_schema` answers in `chat` and `chat_json`;
- sampling settings and an explicit reasoning effort are accepted.

The step is test-only (DEC-005-1). Replanned 2026-11-08 after the token-cap requirement change: DoD-1 and DoD-2 are rewritten, DoD-8 and DoD-9 are new, DoD-3..7 are unchanged. A length stop with no app limit (US-062.AC-6) is not checked live (DEC-005-15). A cut tool answer and a cut checked JSON answer are step 005's (DEC-005-16).

## Interface intent

**Library interfaces.** None added or changed.

**Test file.** It uses `tests.integrations.live_support` (step 001) for clients, keys, models, the recorder and the marker checks. It holds module-local helpers for:

- the long-answer prompt;
- the `json_schema` format with its two required keys;
- the warning filter that counts `LLMSettingIgnoredWarning`;
- the "no library notice" check of DEC-005-12, which records the warnings raised during one call and finds none of the `UserWarning` family.

## Definition of done

1. [test] (live) Non-streamed `chat` with the token cap of DEC-005-8 given as a call option and a long-answer prompt, on both backends (OpenAI with `OPENAI_MODEL`, llama-swap thinking off). The call returns text; no `LLMError` is raised; the answer text is non-empty; the reply holds no reasoning marker; no warning of the `UserWarning` family is recorded during the call (US-062.AC-1, FEAT-010, DEC-arch-13, DEC-005-8, DEC-005-12).
2. [test] (live) The same capped request, streamed with a recorder, on both backends. The call returns text with no `LLMError`; the return equals the joined recorder pieces; its answer text is non-empty; the recorder output passes the well-formed-block check; no warning of the `UserWarning` family is recorded (US-062.AC-2, US-062.AC-3, DEC-arch-13, DEC-005-6, DEC-005-12).
3. [test] (live) Ignored setting, on both backends:
   - two non-streamed `chat` calls on one client, each with the ignored setting of DEC-005-8, both return non-empty text;
   - exactly one `LLMSettingIgnoredWarning` is recorded across the two calls, and its message names the setting;
   - a second client instance called once with the same setting records exactly one more.

   (US-061.AC-1, US-061.AC-2, DEC-003-6, DEC-003-9, DEC-005-8)
4. [test] (live) Non-streamed `chat` with `response_format` of type `json_schema` (today's nested shape) requiring two keys. The reply parses as a JSON object that holds both keys. OpenAI is asserted. The llama-swap variant is marked per DEC-005-9 (US-057.AC-1, US-038.AC-1, DEC-003-10).
5. [test] (live) `chat_json` with the same `json_schema` `response_format` in its options and an expected shape given. The reply parses as a JSON object that holds both required keys. OpenAI is asserted. The llama-swap variant is marked per DEC-005-9 (US-038.AC-1, US-057.AC-1, DEC-003-10).
6. [test] (live) Non-streamed `chat` with `temperature` and `top_p` set, on both backends (OpenAI with `OPENAI_MODEL`). The call returns non-empty text, and no `LLMSettingIgnoredWarning` is recorded (US-019, DEC-003-9).
7. [test] (live) Non-streamed `chat` on OpenAI with `OPENAI_REASONING_MODEL` and an explicit `reasoning_effort` of `"medium"`. The call returns non-empty text that holds no reasoning marker. Skipped without a key (US-025.AC-4, US-028.AC-1, DEC-003-9).
8. [test] (live) `generate` with the token cap of DEC-005-8 as a call option and a long-answer prompt, on both backends, non-streamed and streamed with a recorder. Neither raises `LLMError`. The non-streamed return has non-empty answer text and no reasoning marker. The streamed return has non-empty answer text and equals the joined recorder pieces, and the recorder output passes the well-formed-block check. No warning of the `UserWarning` family is recorded (US-062.AC-1, US-062.AC-2, US-062.AC-3, DEC-000-8, DEC-005-12).
9. [test] (live) Non-streamed `chat` on a client built with the token cap of DEC-005-8 as a client default (`default_options`) and no cap in the call options, with a long-answer prompt, on both backends. The call returns text with non-empty answer text, no `LLMError`, no reasoning marker and no warning of the `UserWarning` family (US-062.AC-1, DEC-arch-13, DEC-005-12).
