# Step 004 — OpenAI client: app credential, streamed errors, empty content, settings

## Goal

Apply every client-level fix to the OpenAI client: it uses only the app's credential, its streamed requests go through the base helper, a reply with no content is empty text, and only the settings the app set — including stop sequences, token bias, end-user id and response format — reach the server.

## Interface intent

- **`OpenAIAPIClient` constructor** (changed): same parameters. Uses the given `bearer_token` only; never reads the environment; a missing or empty credential is refused with `ValueError` per DEC-001-6. The class docstring stops promising environment loading.
- **Supported-settings and alias tables** (changed): no built-in values (DEC-001-13); stop sequences, token bias, end-user id and response format added (DEC-001-14). Alias table unchanged.
- **`_merge_options`** (unchanged logic): still delegates to the base merge and maps the thinking switch (DEC-000-19); it adds nothing when the switch is unset.
- **`chat`** (changed): the streamed branch opens its request through the base streamed-request helper (DEC-001-8) and keeps the trace wrapper rule (DEC-000-48); the non-streamed branch returns empty text for null content (DEC-001-12).
- **`chat_json`** (changed): returns empty text for null content (DEC-001-12); the response-format setting, when the app set one, is sent instead of the JSON-object format (DEC-001-2).
- **`chat_with_tools`** (changed): null content of the final answer and of the recorded assistant tool-call turn becomes empty text (DEC-001-12); the response-format parameter wins over the setting (DEC-001-15).
- **`_tools_stream_request`** (changed, seam kept): same inputs (payload, optional receiver) and outputs (content, tool calls); opens its request through the base streamed-request helper (DEC-001-8).
- **`embed_batch`**: unchanged (DEC-001-16).

## Definition of done

1. [test] An OpenAI client built with a credential sends `Authorization: Bearer <that credential>` on its requests (US-003.AC-1, DEC-001-6).
2. [test] Building an OpenAI client with no credential, or an empty one, raises `ValueError` whose message tells the developer to provide a credential and names no environment variable (US-003.AC-2, DEC-001-6).
3. [test] With `OPENAI_API_KEY` and `OPEN_AI_KEY` set in the environment and no credential passed, building the client is refused (US-003.AC-4, DEC-001-6).
4. [test] The refusal message contains no credential value, including one present in the environment (US-003.AC-3).
5. [test] `get_llm_client("openai", …)` with a credential gives a client that uses it; without one it raises `ValueError` (US-003.AC-1, US-003.AC-2, DEC-001-5).
6. [test] A streamed `chat` that gets a non-2xx reply raises `LLMError` carrying the address, the status and the server's reply, and not the credential (US-011.AC-1, US-011.AC-4, DEC-arch-5).
7. [test] A streamed tool round (`_tools_stream_request`) that gets a non-2xx reply raises the same kind of `LLMError` (US-011.AC-1, DEC-arch-5).
8. [test] A streamed `chat` against an unreachable server raises `LLMError` (US-011.AC-3, DEC-001-7).
9. [test] A streamed `chat` through the helper still gives the receiver every piece in order and returns their concatenation (US-008.AC-1, US-021.AC-2).
10. [test] Non-streamed `chat` and `generate` with null reply content return empty text (US-009.AC-1, DEC-001-12).
11. [test] With tracing switched on, a non-streamed `chat` with null reply content returns empty text (US-009.AC-3, DEC-001-12).
12. [test] `chat_json` with null reply content returns empty text; `chat_with_tools` with a null final answer returns empty text; a tool-call turn with null content enters the next round's conversation with empty text (US-009.AC-1, DEC-001-12).
13. [test] With no settings from the app, the request body of `chat`, `chat_json` and `chat_with_tools` carries no generation setting (no temperature, top-p, penalties, max tokens, seed, reasoning effort) (US-018.AC-1, DEC-001-13).
14. [test] Stop sequences, token bias, end-user id and response format set by the app — as client defaults or per call — appear in the request body of `chat`, `generate` and `chat_with_tools` (US-019.AC-1, DEC-001-14).
15. [test] `chat_json` sends the app's response-format setting when one is set and the JSON-object format otherwise (DEC-001-2).
16. [test] In `chat_with_tools` the response-format parameter is sent when given, even if a response-format setting is set; the setting is sent when the parameter is absent (DEC-001-15).
17. [test] Existing merge rules hold: a per-call `None` removes a client default; `context_length` acts as `max_tokens`; an unknown setting is not sent; a per-call value wins over a client default (US-014.AC-2, US-015.AC-1, US-016.AC-2, US-017.AC-1, US-017.AC-2).
18. [test] Thinking on with no effort sends the default effort; an explicit effort is sent as given; thinking unset sends no effort (US-025.AC-3, US-025.AC-4, DEC-000-19).
19. [test] `embed_batch` sends the call's end-user id over the client's, the client's when the call has none, and no generation setting (US-041.AC-3, US-041.AC-4, DEC-001-16).
20. [test] (live) Every OpenAI live test in the listed integration files reads its key from its own environment, skips when absent, passes it as the credential, and passes against OpenAI (US-003.AC-1).
