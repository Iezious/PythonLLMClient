## Chat-completions frames (consumed format)

- Normal: `data: {"choices":[{"index":0,"delta":{...},"finish_reason":null}]}`; the last content frame carries a non-null `finish_reason` (`stop`, `length`, `tool_calls`, `content_filter`); then `data: [DONE]`. A trailing usage frame may have empty `choices`.
- Error frame (llama.cpp / OpenAI-compatible servers): `data: {"error": {"message": "...", "type": "...", "code": ...}}`, usually without `choices`.

## Gotchas

- Bare CR is a terminator, but a CR at the end of one read followed by LF at the start of the next is one CRLF — do not dispatch an empty line between them (DoD-2).
- Per SSE, a single space after `data:` is removed; JSON payloads do not care, but the multi-line join must keep the newline between lines (DoD-3).
- The transport mapping in the reader must wrap only the reading, not the parser's receiver calls (DoD-13): a receiver runs in the parser, outside the reader's generator frame.
- Tests may pass `response=None` to the parsers when `_iter_sse_data` is monkeypatched; do not make the parsers touch `response` themselves.
