# Step 003 — Stream parsing: complete text, in-stream errors, early end, reasoning with content

## Goal

Make the shared chat-completions stream reader deliver every character and every event intact, and make both stream parsers report a server error frame or an early end as the library error while keeping both reasoning and answer text from one piece.

## Source files

llm/llm_client.py

## Test files

tests/test_llm_sse_stream.py
tests/integrations/test_llm_stream_robustness.py

## Interface intent

- **`LLMClient._iter_sse_data`** (changed): input an open streamed response; yields the data of each server-sent event as one string, with the data lines of a multi-line event joined by a newline (DEC-001-10). Decodes UTF-8 incrementally across reads, honours LF, CRLF and bare CR terminators, ignores comment and non-data fields, and still yields a final event that has no trailing blank line. A transport failure while reading (payload error, disconnect, timeout) raises `LLMError` (DEC-001-7, DEC-001-1). It still yields the `[DONE]` sentinel as a payload; the parsers interpret it.
- **`LLMClient._stream_openai_chat_response`** (changed): same inputs (response, optional receiver) and output (the full text, reasoning tagged). Raises `LLMError` with the server's reason on an error frame (DEC-001-9) and on an early end (DEC-001-1). A piece carrying both reasoning and content delivers both (DEC-001-11). Malformed pieces are skipped as in DEC-001-9.
- **`LLMClient._stream_openai_tools_response`** (changed): same inputs and outputs (content text and tool calls). Same error-frame, early-end and malformed-piece rules as the plain parser. Reasoning and content handling is unchanged (DEC-000-22).
- The coder may add one private helper shared by both parsers for the error-frame and completion checks; it is not a seam and needs no test of its own.

## Definition of done

1. [test] A multi-byte character whose bytes are split across two reads reaches the receiver whole and is in the returned text (US-036.AC-1, US-036.AC-3, DEC-001-10).
2. [test] The same stream terminated with LF, with CRLF and with bare CR yields the same events; a CRLF split across two reads counts as one terminator and does not end an event early (US-036.AC-2, DEC-001-10).
3. [test] An event whose data spans several `data:` lines is yielded once, its lines joined by a newline (US-036.AC-2, DEC-001-10).
4. [test] Comment lines and `event:` / `id:` / `retry:` lines are ignored; a final event not followed by a blank line is still yielded (DEC-001-10).
5. [test] A payload error, disconnect or timeout raised while the reader is reading raises `LLMError` (US-024.AC-2, US-011.AC-3, DEC-001-1, DEC-001-7).
6. [test] Plain parser: an error frame raises `LLMError` whose text carries the server's reason; no piece after it reaches the receiver (US-024.AC-1, DEC-001-9).
7. [test] Tools parser: an error frame raises `LLMError` whose text carries the server's reason (US-024.AC-1, DEC-001-9).
8. [test] Plain parser: a stream that ends with neither a finish reason nor `[DONE]` raises `LLMError`; one with only `[DONE]`, or only a finish reason on the last choice, returns normally (US-024.AC-2, DEC-001-1).
9. [test] Tools parser: same end-of-stream rule as DoD-8 (US-024.AC-2, DEC-001-1).
10. [test] Plain parser: a piece carrying both reasoning and content gives the receiver the reasoning first (opening marker if it starts the block) and then the content (closing marker before it); the returned text equals what the receiver got (US-026.AC-5, US-026.AC-4, DEC-001-11).
11. [test] Both parsers skip a non-JSON data payload, a JSON payload that is not an object, and an object without choices and without an error, without raising; text from the other pieces arrives intact (DEC-001-9).
12. [test] Plain parser keeps today's reasoning rules: one marked block before the answer, closed at the end if still open, none for a model that does not reason (US-026.AC-1, US-026.AC-2, US-026.AC-3).
13. [test] A receiver failure in either parser ends the call with that same exception and no later piece is delivered (US-022.AC-1, US-022.AC-2, DEC-000-23).
14. [test] `tests/test_llm_tools_reasoning_stream.py` passes unchanged (US-027.AC-1, US-027.AC-2).
15. [test] (live) On llama-swap, a streamed chat whose reply contains non-English characters delivers every character to the receiver and returns the same text (US-036.AC-1, US-036.AC-3, US-021.AC-1).
16. [test] (live) Same as DoD-15 on OpenAI; the test reads its key from its own environment, passes it as the credential, and skips when absent (US-036.AC-1, US-036.AC-3).
